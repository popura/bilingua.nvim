*bilingua.txt*	Bilingual source/target editing with Codex or llama-server

==============================================================================
Bilingua.nvim						*bilingua*

Bilingua.nvim は、原文 (source) と日本語訳 (target) を並べ、双方の編集を
mapping group 単位で同期する非永続の Neovim plugin です。

標準 backend は Codex app-server と local llama-server です。既定は Codex
app-server です。Session の開始時に target scratch buffer を作成し、停止時に
plugin 所有の buffer、window、extmark、autocmd、timer、mapping graph、task、
backend resource を解放します。利用者所有の llama-server は停止しません。

==============================================================================
1. Requirements					*bilingua-requirements*

- Neovim 0.10 以上。
- Codex backend には Codex CLI 0.146.0 以上、利用可能な認証、text input
  対応 model。
- llama-server backend には curl、外部で起動した llama-server、対応 chat
  template を持つ instruct model。
- 外部 Lua runtime dependency はありません。

0.146.0 は本 project が app-server の生成 schema を確認した最低版です。
protocol は Codex の版に依存するため、更新時は
|bilingua-codex-compatibility| の検査を実行してください。
llama-server backend の互換基準と起動方法は |bilingua-llama-server| を参照して
ください。


準備状況の確認例: >

  codex --version
  codex login
  codex app-server --help
  llama-server --version
  curl --version
<

==============================================================================
2. Setup						*bilingua-setup*

runtimepath に plugin を追加した後、init.lua で次を実行します。 >

  require("bilingua").setup()
<

setup() は省略できます。省略時も既定設定で command が使えます。設定例と
全項目は |bilingua-configuration| を参照してください。

source として使用できるのは、非空の file path を持つ loaded、modifiable、
non-binary の通常 buffer です。未保存の無名 buffer、特殊 buftype、read-only
buffer は E_INVALID_SOURCE_BUFFER です。

==============================================================================
3. Quick start					*bilingua-quick-start*

1. 編集可能な原文 buffer を開きます。
2. :BilinguaStart または <leader>bs を実行します。
3. source または target を編集します。
4. 自動同期を待つか、:BilinguaSync を実行します。
5. conflict では正しい側を確認し、:BilinguaUseSource または
   :BilinguaUseJapanese を実行します。
6. source を残して終了するには :BilinguaStop を実行します。

source language を固定する例: >

  :BilinguaStart en
<

既定 target language は ja です。target は
"bilingua://ja/{buffer}/{name}" という名前の scratch buffer であり、通常の
file として保存されません。

==============================================================================
4. Commands						*bilingua-commands*

							*:BilinguaStart*
:BilinguaStart [source-language]
	現在 buffer で Session を開始します。引数省略時は setup() の
	source_language を使います。処理中に編集された場合、debounce 後の
	最新 source から初期翻訳を再開します。

:BilinguaStart! [source-language]
	既存 Session を force stop して、同じ source buffer で新しい
	Session を開始します。未同期 target edit と conflict は破棄されます。

							*:BilinguaToggle*
:BilinguaToggle
	source と target の focus を切り替えます。target window が閉じている
	場合は再表示します。

							*:BilinguaSync*
:BilinguaSync
	cursor 下の mapping group を即時同期します。source 側なら target へ、
	target 側なら source へ同期します。

							*:BilinguaSyncAll*
:BilinguaSyncAll
	現在 Session の conflict 以外の dirty／invalid group を再評価して
	同期します。同時実行数は sync.max_concurrency に従います。

							*:BilinguaUseSource*
:BilinguaUseSource
	cursor 下の conflict で source を正とし、target を更新します。
	conflict でない group には使用できません。

							*:BilinguaUseJapanese*
:BilinguaUseJapanese
	cursor 下の conflict で target を正とし、source を更新します。
	conflict でない group には使用できません。

							*:BilinguaNext*
:BilinguaNext
	次の mapping group へ移動します。

							*:BilinguaPrev*
:BilinguaPrev
	前の mapping group へ移動します。

							*:BilinguaStatus*
:BilinguaStatus
	現在 Session の本文を含まない状態のコピーを vim.notify() で表示します。
	詳細は |bilingua-status| を参照してください。

							*:BilinguaRetry*
:BilinguaRetry
	Session があれば cursor 下の group を最新 revision で再試行します。
	開始に失敗した直後で Session がなければ、現在 source buffer に保存した
	options の copy から新しい Session を構築して開始を再試行します。
	document content や失敗 Session 自体は retry 用に保持しません。

						*:BilinguaRestartBackend*
:BilinguaRestartBackend
	現在の source/target snapshot と mapping graph を保ったまま
	TranslationService/backend を閉じ、新しい instance を開きます。
	成功すると health を healthy にし、自動同期の pause を解除します。

							*:BilinguaStop*
:BilinguaStop
	Session だけを正常停止し、source buffer は開いたまま残します。
	未同期 target edit は stop.sync_pending に従って source へ同期します。
	conflict、invalid、backend error、timeout が残れば停止を中止します。
	source-only edit は source buffer 自体に残るため、終了時の翻訳 task は
	作りません。

:BilinguaStop!
	active task を cancel し、未同期 target edit と conflict を破棄して
	Session を force stop します。source へ適用済みの edit は戻しません。

							*:BilinguaQuit*
:BilinguaQuit
	:BilinguaStop 相当の正常停止後、source buffer を Neovim 標準の
	confirm bdelete 相当で閉じます。保存、破棄、cancel の判断は Neovim
	に委ねます。

:BilinguaQuit!
	:BilinguaStop! の後、source buffer も force delete します。未保存の
	source edit を失います。既定 mapping はありません。

==============================================================================
5. Mappings						*bilingua-mappings*

mappings.start だけが global です。それ以外は Session の source/target
buffer-local で、Session 停止時に削除されます。

  <leader>bs	<BilinguaStart>
  <leader>bb	<BilinguaToggle>
  <leader>by	<BilinguaSync>
  <leader>ba	<BilinguaSyncAll>
  <leader>bo	<BilinguaUseSource>
  <leader>bj	<BilinguaUseJapanese>
  ]b		<BilinguaNext>
  [b		<BilinguaPrev>
  <leader>bq	<BilinguaStop>
  <leader>bQ	<BilinguaQuit>

実際の右辺は次の <Plug> mapping です。

  <Plug>(BilinguaStart)			*<Plug>(BilinguaStart)*
  <Plug>(BilinguaToggle)		*<Plug>(BilinguaToggle)*
  <Plug>(BilinguaSync)			*<Plug>(BilinguaSync)*
  <Plug>(BilinguaSyncAll)		*<Plug>(BilinguaSyncAll)*
  <Plug>(BilinguaUseSource)		*<Plug>(BilinguaUseSource)*
  <Plug>(BilinguaUseJapanese)		*<Plug>(BilinguaUseJapanese)*
  <Plug>(BilinguaNext)			*<Plug>(BilinguaNext)*
  <Plug>(BilinguaPrev)			*<Plug>(BilinguaPrev)*
  <Plug>(BilinguaStatus)		*<Plug>(BilinguaStatus)*
  <Plug>(BilinguaRetry)			*<Plug>(BilinguaRetry)*
  <Plug>(BilinguaRestartBackend)	*<Plug>(BilinguaRestartBackend)*
  <Plug>(BilinguaStop)			*<Plug>(BilinguaStop)*
  <Plug>(BilinguaQuit)			*<Plug>(BilinguaQuit)*

Status、Retry、RestartBackend、force Quit には既定 key を割り当てません。
mappings.enabled=false で既定 mapping をすべて無効にできます。各 mapping
には string または false を指定できます。

						*bilingua-config-language*
source_language
	非空 string。既定 "auto"。start({source_language=...}) または
	:BilinguaStart の引数で Session ごとに上書きできます。
target_language
	非空 string。既定 "ja"。

						*bilingua-config-mappings*
mappings.enabled
	boolean。既定 true。
mappings.start/toggle/sync/sync_all/use_source/use_japanese/next/prev/stop/quit
	string または false。値は |bilingua-mappings| を参照してください。

						*bilingua-config-layout*
layout.direction
	"vertical" または "horizontal"。
layout.target_position
	"right"、"left"、"above"、"below"。vertical では right/left、
	horizontal では above/below を使用してください。
layout.size
	0 より大きく 1 より小さい比率、または正の整数。
layout.follow_cursor
	true のとき、反対側 window が見えていれば対応 group を表示します。
	focus は奪いません。
layout.follow_debounce_ms
	0 以上の整数。
layout.open_folds
	true なら cursor follow の移動先にある fold を開きます。
	既定 false。focus と移動先 window の scroll view は保持します。

						*bilingua-config-sync*
sync.automatic
	変更後に task を自動作成するか。既定 true。
sync.debounce_ms
	変更をまとめる待機時間。0 以上の整数。
sync.on_insert_leave
	true のとき InsertLeave で待機中の自動同期を flush します。
sync.max_concurrency
	TranslationService へ同時 submit する異なる group 数。正の整数。
sync.context_groups
	task に付ける前後の bilingual group 数。replacement scope は広げません。
sync.structural_changes
	"auto_safe" は安全に対応できる追加・削除・分割・結合を同期します。
	"manual" は structural edit を conflict にし、"disabled" は invalid に
	します。
sync.conflict_policy
	初期版では "manual" だけを受理します。
sync.retry.max_attempts
	retryable backend error の最大試行数。正の整数。
sync.retry.initial_delay_ms / sync.retry.max_delay_ms
	bounded exponential backoff の初期／最大 delay。0 以上の整数で、
	maximum は initial 以上でなければなりません。

						*bilingua-config-stop*
stop.sync_pending
	true なら正常停止時に dirty_target を source へ同期します。false で
	dirty_target が残る場合、正常停止は失敗します。
stop.timeout_ms
	正常停止の最大待機時間。正の整数。

						*bilingua-config-persistence*
persistence.enabled
	初期版では false のみ。true は E_INVALID_ARGUMENT です。

						*bilingua-config-limits*
limits.max_document_bytes
	parse 前の document byte 上限。
limits.max_units
	parse 後の unit 数上限。
limits.max_task_input_chars / max_task_output_chars
	一つの translation task の入力／出力文字数上限。
limits.initial_batch_chars / initial_batch_units
	初期翻訳 batch の最大文字数／unit 数。
	単一 unit が文字数上限を超える場合は分割も送信もせず、
	E_DOCUMENT_TOO_LARGE で開始を中止します。
	すべて正の整数です。

						*bilingua-config-documents*
documents.fallback_to_plaintext
	一致する route がない filetype を plaintext として扱うか。
documents.aliases
	alias filetype から documents.routes の key への table。
documents.protected_patterns
	追加で保護する有効な Lua pattern の連続した string list。空 list を含む
	Session ごとの値は global list を要素単位で merge せず置き換えます。
documents.routes
	filetype ごとの {adapter, tracker, aligner}。完全一致、alias の順で
	解決します。各 component は registry に登録済みである必要があります。

						*bilingua-config-translation*
                                *bilingua-translation-backends*
translation.service
	TranslationService factory ID。
translation.backend
	InferenceBackend factory ID。既定 "codex_app_server"。
translation.initial_codec / translation.patch_codec
	初期翻訳／incremental semantic patch の TaskCodec factory ID。
translation.timeout_ms
	turn／task timeout。正の整数。
translation.backends
        backend ID ごとの option table。標準 ID は "codex_app_server" と
        "llama_server" です。選択した backend の table だけを Session ごとに
        copy し、他 backend の option は混入しません。custom backend ID と option
        key も登録できます。

                        *bilingua-translation-backend-options*
translation.backends.codex_app_server.command
	non-empty string の argv list。shell 文字列ではありません。
translation.backends.codex_app_server.model
	使用する text model。既定 "gpt-5.6-luna"。
translation.backends.codex_app_server.reasoning_effort
	使用する reasoning effort。既定 "max"。推論時間と token 使用量が
	増える場合があるため、速度を優先する用途では明示的に下げてください。
translation.backends.codex_app_server.require_ephemeral
	true なら thread.ephemeral=true の確認を必須にします。
translation.backends.codex_app_server.strict_isolation
	true なら backend instance ごとの permission profile と isolated cwd を
	使い、各 task で isolation directory だけを read-only workspace root に
	します。
	false は Codex 標準 readOnly sandbox に戻り、directory 外も読み取り
	可能になるため、通常は変更しないでください。
translation.backends.codex_app_server.reject_external_instruction_sources
	true なら instructionSources を document 送信前に検証します。isolated
	cwd 内、または Bilingua 初期化時に検出した Codex user-level
	AGENTS.override.md／AGENTS.md と realpath で同一の file だけを許可し、
	それ以外を拒否します。
translation.backends.codex_app_server.include_platform_default_reads
	旧設定との互換性のための option。true は strict_isolation=true と
	同時には指定できません。非 strict mode の標準 readOnly sandbox を
	狭めるものではありません。
translation.backends.codex_app_server.experimental_api
	initialize capability の experimentalApi。既定 true。
	strict_isolation=true では permission profile API に必要なため、false と
	同時には指定できません。
translation.backends.codex_app_server.request_timeout_ms
	initialize/model/thread/turn start RPC の timeout。
translation.backends.codex_app_server.shutdown_timeout_ms
	backend shutdown 後に process を強制終了するまでの待機時間。

translation.backend_options
        旧設定との互換用 overlay。選択中の translation.backends.<id> に
        deep-merge され、同じ key では backend_options が優先されます。
        command list は要素 merge せず list 全体を置き換えます。新規設定では
        backend 間の option 混入を避けるため backend 別 table を使用して
        ください。resolved config では選択 backend の互換 mirror になります。

                                *bilingua-llama-server*
llama-server prerequisites ~
llama backend は次を必要とします。

- PATH 上の curl。
- 利用者が外部で起動した llama-server。
- 対応 chat template を持つ instruct model。

Bilingua は server や model を download／起動しません。model 固有の GPU
option や context size を固定しない最小起動例: >

  llama-server \
    -m /path/to/model.gguf \
    --host 127.0.0.1 \
    --port 8080 \
    --alias local-translator
<

選択例: >

  require("bilingua").setup({
    translation = {
      backend = "llama_server",
      backends = {
        llama_server = {
          endpoint = "http://127.0.0.1:8080",
          model = "auto",
          structured_output = "json_schema",
          disable_thinking = true,
        },
      },
    },
  })
<

構造化出力は OpenAI-compatible な nested 形式
response_format.json_schema.schema を使います。2026-08-04 時点の
llama.cpp source、GBNF guide、および実際の loopback server で確認しました。
https://github.com/ggml-org/llama.cpp/blob/master/tools/server/server-common.cpp
https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md

translation.backends.llama_server.endpoint
        HTTP loopback authority。127.0.0.1、localhost、[::1] だけを受理し、
        path、query、fragment、userinfo、remote host、TLS を拒否します。
        既定 "http://127.0.0.1:8080"。認証 header と redirect は使いません。
translation.backends.llama_server.model
        llama-server へ渡す model ID。既定 "auto"。auto は /v1/models に
        non-empty ID がちょうど一つある場合だけ採用します。複数 model の
        server では ID を明示してください。
translation.backends.llama_server.curl_command
        curl の argv prefix。既定 {"curl"}。shell 文字列ではありません。
translation.backends.llama_server.open_timeout_ms
        health polling と model discovery 全体の timeout。正の整数。
        既定 30000。
translation.backends.llama_server.health_poll_interval_ms
        /health が loading の HTTP 503 を返した後の poll 間隔。正の整数で、
        open_timeout_ms 以下。既定 250。
translation.backends.llama_server.request_timeout_ms
        一つの Chat Completions request の timeout。0 は
        translation.timeout_ms を使います。既定 0。
translation.backends.llama_server.structured_output
        "json_schema" または "prompt_only"。既定 "json_schema"。
        json_schema は response_format.json_schema.schema と prompt の両方へ
        Schema を入れます。prompt_only は API parameter を省略し、prompt
        だけへ Schema を入れます。
translation.backends.llama_server.disable_thinking
        true なら reasoning_effort="none" と
        chat_template_kwargs.enable_thinking=false を request に加えます。
        既定 true。実際の挙動は model の chat template に依存します。
translation.backends.llama_server.max_response_bytes
        curl stdout の byte 上限。正の整数。既定 16 MiB。

llama-server errors and remedies ~
  E_BACKEND_NOT_FOUND
        curl を起動できません。PATH と curl_command を確認します。
  E_BACKEND_UNAVAILABLE
        connection refused、network failure、HTTP 5xx。server process、host、
        port を確認します。一時的失敗だけ retry 対象です。
  E_BACKEND_TIMEOUT
        open または request timeout。model loading 中なら open_timeout_ms、
        inference 中なら model context、prediction limit、task size を確認します。
  E_BACKEND_INIT
        endpoint／option が不正、または model="auto" で ID が一つに決まり
        ません。/v1/models を確認し、必要なら model ID を明示します。
  E_BACKEND_PROTOCOL
        health、model list、Chat Completions envelope が不正、response が途中で
        切れた、または Schema request が拒否されました。llama.cpp version と
        server log を確認し、Schema 非対応時は prompt_only を試します。
  E_BACKEND_TOOL_ATTEMPT
        model が tool call を返しました。tool は送信していないため適用せず、
        model と chat template を確認します。
  E_INVALID_OUTPUT
        codec JSON、unit ID、destination、placeholder、出力上限の検証失敗。
        model 能力、chat template、task size を確認します。

llama-server privacy and lifecycle ~
endpoint は loopback に限定しますが、同一 host 内の process と server 自体は
Bilingua の信頼境界外です。文書の機密性、model license、model file の権限、
server の log／cache／telemetry、CPU／GPU／memory は利用者が管理してください。
Codex の permission profile は llama-server process へ適用されません。

|:BilinguaStop| と |:BilinguaStop!| は active curl request と plugin 所有 timer
を cancel します。shutdown endpoint は呼ばず、利用者所有の llama-server
process は Session 終了後も稼働を続けます。

						*bilingua-config-ui*
ui.signs / ui.virtual_text
	mapping group state の sign／行末 virtual text を表示するか。
ui.notify_backend
	true なら BilinguaError の実行時 backend error を固定文と正規化 code で
	vim.notify() します。同じ Session／code は 1 秒間、重複表示しません。
	false はこの通知だけを無効化し、command error 表示には影響しません。
ui.show_progress
	true なら初期翻訳の完了 batch 数を target 先頭行の
	"Translating completed/total…" virtual text に表示します。開始完了、
	失敗、再開始、停止時に消去します。false はこの初期進捗だけを
	無効にします。group 状態表示は ui.signs/ui.virtual_text が制御します。

						*bilingua-config-debug*
debug.enabled
	初期版では追加の payload 診断を有効にしません。
debug.log_payloads
	初期版では false のみ。true は E_INVALID_ARGUMENT です。
debug.ring_size
	backend stderr の in-memory ring buffer 最大件数。正の整数。

setup() は型・値域を検証します。未知の key は typo 検出のため警告します。
documents.routes、documents.aliases、translation.backends、
translation.backend_options は
extension 用の動的 key を受け入れます。

7. Document handling					*bilingua-documents*

						*bilingua-plaintext*
Plaintext adapter は空行で区切られた paragraph を unit とします。CRLF/LF と
最終改行の有無を保持します。各 unit 内の inline code、URL、link destination、
reference label、HTML tag、template、printf placeholder、inline math を
protected token として扱います。

						*bilingua-markdown*
Markdown route は、利用可能なら Neovim の Markdown Tree-sitter parser と
queries/markdown/bilingua.scm を解析・検証に使用します。parser または query
が利用できない場合、documents.fallback_to_plaintext=true なら警告して
Plaintext adapter を使い、false なら E_PARSE で Session 開始を中止します。
Bilingua の構文 template 抽出は完全な CommonMark 実装ではありません。

翻訳対象:
- ATX/Setext heading。
- paragraph。
- ordered/unordered list item。
- blockquote paragraph。

opaque unit として翻訳せず mirror する構造:
- YAML/TOML style front matter。
- fenced/indented code。
- $$ math block。
- table。
- HTML block/comment。
- thematic break。
- reference definition。
- image だけの行。

opaque unit は raw text が両側で一致するように同期します。未閉鎖の opaque
block、構造を安全に維持できない edit、protected token 不一致は適用しません。

						*bilingua-protected-tokens*
protected token は model へ placeholder として渡し、返却時に個数・identity・
重複を完全一致で検証してから元 literal を復元します。文書中の命令は data
であり、system/developer instruction には連結しません。
documents.protected_patterns の各 Lua pattern に一致した literal も同じ方法で
保護します。

==============================================================================
8. Synchronization				*bilingua-synchronization*

mapping group は source unit 群、target unit 群、baseline triple、state を
保持します。1 対 1 だけでなく split/merge を表現できます。

state:
  clean				baseline と一致
  dirty_source			source に未同期 edit
  dirty_target			target に未同期 edit
  syncing_source_to_target	source から target へ処理中
  syncing_target_to_source	target から source へ処理中
  conflict			両 side edit または対応が曖昧
  invalid			parse/result/apply 検証に失敗

表示記号:
  ✓ clean	S dirty_source	J dirty_target
  … syncing	! conflict		× invalid

同じ group が再編集されると active task の cancel を要求します。cancel の成否
だけには依存せず、task revision と destination document version を適用直前に
再検証します。stale result は適用せず、最新 revision を再同期します。

programmatic edit は Editor の apply guard で user edit と区別します。一つの
同期適用は可能な範囲で一つの undo step にまとめます。

conflict は自動 merge しません。|:BilinguaUseSource| または
|:BilinguaUseJapanese| で方向を明示してください。

==============================================================================
9. Status and recovery					*bilingua-status*

|:BilinguaStatus| は次を表示します。

- Session state と health。
- source path/buffer、target buffer。
- source/target language。
- document adapter、tracker、aligner。
- backend と解決済み model。
- state ごとの group 数。
- active task 数。
- effective automatic sync state: enabled、disabled、paused。

health:
  starting	Session/backend の初期化中
  healthy	同期可能
  degraded	error 後で手動操作または復旧が必要
  stopping	停止処理中
  disposed	plugin 所有 resource を解放済み

backend failure、protocol/auth/isolation error、tool attempt、invalid output では
health が degraded になり、自動同期を pause します。個別 group は
|:BilinguaRetry|、backend 全体は |:BilinguaRestartBackend| で復旧します。
restart 成功時は document state を保持し、pause を解除します。

10. Lua API						*bilingua-api*

公開 module: >

  local bilingua = require("bilingua")

  bilingua.setup(opts)
  bilingua.start(opts, callback)
  bilingua.toggle()
  bilingua.sync_current()
  bilingua.sync_all()
  bilingua.use_source()
  bilingua.use_japanese()
  bilingua.next_group()
  bilingua.prev_group()
  bilingua.retry_current(callback)
  bilingua.restart_backend(callback)
  bilingua.stop({ force = false }, callback)
  bilingua.quit({ force = false }, callback)
  bilingua.status()
<

start options は setup options を Session 単位で上書きします。top-level
backend は translation.backend の short form です。 >

  require("bilingua").start({
    source_language = "fr",
    target_language = "ja",
    backend = "codex_app_server",
  }, function(status, err)
    if not status then
      vim.notify(err.message, vim.log.levels.ERROR)
    end
  end)
<

start、retry_current、restart_backend、stop、quit は callback で非同期完了を
通知できます。開始受付の boolean と即時 error も返します。

status() は内部 Session table と共有されない状態のコピーを返します。本文、
prompt、model response、認証情報を含みません。主な field は session_id、
state、health、source_buf、source_path、target_buf、languages、component ID、
backend/model、groups、active_tasks、automatic_sync、
automatic_sync_configured、automatic_sync_paused です。

12. Extension registry					*bilingua-registry*

  local registry = require("bilingua.registry")

  registry.register_unit_tracker("my_tracker", factory)

14. Security and privacy				*bilingua-security*

信頼境界 ~
Bilingua.nvim は source/target を信頼できない document data として扱います。
文書中の prompt、command、URL、認証情報取得要求を instruction として実行
しません。TaskCodec は固定 system/developer instruction と JSON document
data を分離します。

Codex strict isolation ~
backend instance ごとに隔離資源を作り、各 translation task の ephemeral
thread で次の制約を適用します。

- backend instance ごとに空の一時 directory を作り、app-server process と
  各 thread／turn の cwd にする。
- source path、source directory、他の workspace、Neovim buffer handle、
  Neovim RPC 情報を request/readable root に含めない。
- ephemeral thread を要求し、thread.ephemeral=true を確認する。
- thread/start の instructionSources が list であり、各 file が isolated cwd
  内、または Bilingua 初期化時に検出した Codex user-level
  AGENTS.override.md／AGENTS.md と realpath で同一であることを document data
  送信前に確認する。それ以外の instruction source は拒否する。
- backend instance ごとに推測困難な名前の permission profile を定義し、
  各 task で isolated cwd だけを read-only workspace root として許可する。
- network を無効化し、空の environments で local environment access を
  無効化する。
- approvalPolicy="never" を指定し、server-initiated approval、permission、
  elicitation、user-input request を安全に decline/cancel する。
- commandExecution、fileChange、MCP/dynamic tool、webSearch、imageView、
  collab/subagent item を検出した task を interrupt し、出力を適用しない。
- model output は schema、task ID、revision、document structure、
  protected token、destination version を検証してから Editor だけが適用する。

重要: approvalPolicy="never" 単独は tool-disable option ではありません。
permission profile、local environment access 無効化、isolated cwd、item 検出、
prompt は多層防御です。より強い保証が必要なら、利用者または配布環境が
codex app-server process を外部 sandbox へ収容してください。

Codex home（$CODEX_HOME、未設定時は ~/.codex）に上記の user-level
instruction file が存在すると、Codex app-server はその内容を model
instruction として読み込む場合があります。Bilingua は file の内容を変更
しません。翻訳に影響し得るため、利用者はこれらの file も確認してください。

llama-server trust boundary ~
llama backend は tool 定義を送らず、endpoint を HTTP loopback に限定します。
ただし Codex の permission profile、isolated cwd、network off は利用者所有の
llama-server process へ適用されません。同一 host 上の他 process、server、
model、chat template、model file は Bilingua の信頼境界外です。server と
model file の権限を設定し、不要な interface へ bind しないでください。
詳細は |bilingua-llama-server| を参照してください。

data transfer and retention ~
Codex app-server は local process ですが、選択 model によって document
content が外部 OpenAI service へ送信される場合があります。plugin は機密
情報を自動検出・匿名化しません。送信前に内容と backend を確認してください。

plugin が state を永続化しないことは、Codex、OpenAI、llama-server、model、
または custom provider が独自に request、log、cache、telemetry を保持しない
ことを保証しません。各 provider と model の方針を別に確認してください。

credentials and logs ~
API key を setup table、document、TranslationTask metadata、error、target
buffer、log に書かないでください。provider 公式認証、環境変数、OS credential
store を使用してください。

既定診断は ID、component/model、status、error code、size/timing 相当の
metadata に限定します。payload logging は実装せず、
debug.log_payloads=true を拒否します。User event にも本文を含めません。

15. Non-persistence				*bilingua-non-persistence*

target buffer:
  buftype=nofile
  bufhidden=hide
  buflisted=false
  swapfile=false
  undofile=false

plugin は sidecar、target file、mapping cache、SQLite database、target の
persistent undo、swap/backup、prompt/response transcript、resume file を
作りません。Codex 用一時 directory は backend close 時に再帰削除します。
llama backend は client 側 curl と timer だけを所有し、外部 llama-server の
process、model、log、cache を削除または停止しません。

normal stop では active work の完了と必要な target-to-source sync を待ち、
error/conflict が残れば target を維持して停止を中止します。force stop、
source/target buffer detach、VimLeavePre では待たずに task を cancel し、
plugin 所有 resource を解放します。

source buffer の swapfile、undofile、backup、writebackup は変更せず、自動保存
もしません。source の通常 undo/history、Neovim 自身の file、package manager
が管理する plugin、利用者設定、provider 側保持は非永続性の対象外です。

target window を :close しただけなら bufhidden=hide により Session は残り、
|:BilinguaToggle| で再表示できます。target buffer 自体の bdelete/bwipeout は
未同期内容の force disposal に相当します。安全な終了には
|:BilinguaStop| を使用してください。

16. Compatibility and testing				*bilingua-development*

						*bilingua-codex-compatibility*
Codex app-server schema の確認: >

  sh scripts/check-codex-schema.sh
<

この script は次を行います。

- mktemp で一時 directory を作る。
- codex app-server generate-json-schema --experimental を実行する。
- initialize、model/list、thread/start、turn/start、turn/interrupt の schema
  file を確認する。
- ephemeral、instructionSources、approvalPolicy、sandbox、permission profile
  関連 field を確認する。
- 終了時に一時 directory を削除する。

通常 test は Codex、llama-server、認証、network を使わず、fake transport と
fake app-server を使用します。 >

  sh scripts/test.sh
  stylua --check lua plugin tests scripts/benchmark.lua scripts/benchmark_runner.lua scripts/live_codex_test.lua scripts/live_llama_test.lua scripts/live_llama_session_test.lua
  luacheck lua plugin tests scripts/benchmark.lua scripts/benchmark_runner.lua scripts/live_codex_test.lua scripts/live_llama_test.lua scripts/live_llama_session_test.lua
  nvim --headless -u NONE -c "helptags doc" -c "qa!"
<

認証済み Codex へ固定 marker を1回送る live test は明示的 opt-in です。応答
本文は表示せず、標準 backend の gpt-5.6-luna／max、structured output、backend
cleanup を検証します。外部 service への送信と利用料金が発生し得ます。 >

  BILINGUA_RUN_LIVE_CODEX=1 sh scripts/test-live-codex.sh
<

llama live test は利用者が事前に起動した loopback server に対する明示的
opt-in です。server／model を download または起動しません。既存 codec で
初回翻訳と semantic patch を一件ずつ行い、protected placeholder、timeout、
cleanup と close 後の health を検証します。response content と model ID は
表示しません。 >

  BILINGUA_RUN_LIVE_LLAMA=1 \
  BILINGUA_LLAMA_SERVER_URL=http://127.0.0.1:8080 \
  BILINGUA_LLAMA_SERVER_MODEL=auto \
  sh scripts/test-live-llama.sh
<

公開 Ex command、双方向 sync、status、active request の force stop まで確認する
session smoke test も同じ opt-in と固定の合成 plaintext を使います。 >

  BILINGUA_RUN_LIVE_LLAMA=1 \
  BILINGUA_LLAMA_SERVER_URL=http://127.0.0.1:8080 \
  BILINGUA_LLAMA_SERVER_MODEL=auto \
  sh scripts/test-live-llama-session.sh
<

別の Neovim executable では BILINGUA_NVIM=/absolute/path/to/nvim も指定します。

型・静的検査方針は全 file で共通です。Lua 5.1 構文を使い、単一の
.luacheckrc で vim だけを global として許可し、個別 file の抑制は
置きません。extension は api_version=1 と必須 method を SessionFactory
で runtime contract-check し、同じ contract test を各実装へ適用します。


既定上限に近い 2,000 unit の Plaintext/Markdown parse と Hybrid Tracker の
benchmark: >

  sh scripts/benchmark.sh
<

結果は Neovim 版、unit 数、byte 数、反復数と min/median/max を表示します。
機種差が大きいため合否閾値は設けません。短い確認では環境変数
BILINGUA_BENCHMARK_UNITS、BILINGUA_BENCHMARK_ITERATIONS、
BILINGUA_BENCHMARK_PAYLOAD_BYTES を小さくできます。

CI は Neovim 0.10.4、stable、allowed-failure の nightly を対象にします。
format、lint、unit/contract/integration、fake app-server、25 回の resource
cleanup stress test を実行します。最新 Codex schema は週次・手動で確認
します。Codex と llama の live test は認証、server、model availability、
network に依存するため通常 CI では実行しません。
